# Cross-Framework Mapping Dataflow

> How a control's cross-framework neighbors flow from the upstream source of truth all the way to a pixel rendered in the user's browser. Read this before changing anything in `src/data/_raw/CONTROLS.json`.

---

## End-to-end pipeline

```
  prinnyo/grc-framework-mapping-tool                (upstream, single HTML file)
            |
            |  git fetch upstream
            |  git show upstream/main:grc_framework_mapping.html
            v
  tmp/upstream/grc_framework_mapping.html           (gitignored)
            |
            |  npm run extract:upstream
            |  (scripts/extract-upstream-controls.mjs)
            |  vm.runInNewContext sandbox eval of
            |  `var CLAUSES=[...]; var CONTROLS=CLAUSES.concat([...])`
            v
  tmp/upstream/controls.json                        (118 IsoControls, gitignored)
            |
            |  scripted diff (node one-liner in docs/UPSTREAM_DIFF.md)
            v
  docs/UPSTREAM_DIFF.md                             (forensic record)
  docs/MAPPING_DIFF.md                              (if drift surfaces; currently empty)
            |
            |  any reconciliation edits
            v
  src/data/_raw/CONTROLS.json                       (PROJECT SOURCE OF TRUTH)
            |
            |  src/data/schemas.ts (Zod parse at module load)
            v
  src/data/frameworks/iso27001.ts                   (validated, frozen)
            |
            |  exports iso27001Controls / managementClauses / annexA
            v
  src/domain/mapping-engine.ts
            |  parseCrossRefs(value)          comma-separated -> string[]
            |  getMappingsForControl(c)       control -> ControlMappings
            |  getIsoControlsForRef(...)      reverse lookup
            |  getTransitiveMappings(...)     framework-pair transitive
            v
  Integrity layer (always-on)
  src/domain/mapping-integrity.test.ts
            |  zero-orphan invariant
            |  inbound-reference invariant
            |  reverse round-trip invariant
            |  -> CI gate before typecheck
            v
  UI layer
  - MappingBadges.tsx                       (compact, populated-only)
  - ControlNeighborhoodView.tsx             (full 10-row grid, em-dash on empties)
  - ControlNeighborhoodPage.tsx             (route /neighborhood/iso/:id, click-to-navigate)
```

## Where to make changes

| You want to ... | Edit | Then verify with |
|-----------------|------|------------------|
| Add a new framework as a cross-ref target | `src/data/schemas.ts` (add field to IsoControl), `src/data/_raw/CONTROLS.json` (populate), `src/data/frameworks/<new>.ts`, `src/domain/mapping-engine.ts` (add to `frameworkPropKeys`) | `npm run validate:mappings && npm test && npm run test:e2e` |
| Repair a stale cross-ref on an existing control | `src/data/_raw/CONTROLS.json` only | `npm run validate:mappings` + spot-check `tmp/mapping-orphans.json` |
| Improve neighborhood UI styling/layout | `src/features/controls/ControlNeighborhoodView.tsx` | `npm test src/features/controls/ControlNeighborhoodView.test.tsx && npm run test:e2e -- control-neighborhood` |
| Change reverse-lookup or transitive math | `src/domain/mapping-engine.ts` | `npm test src/domain/mapping-engine.test.ts` (100% coverage gate) + `npm run validate:mappings` |
| Sync against latest upstream prinnyo | `git fetch upstream && npm run extract:upstream` and diff. Reconcile by editing `src/data/_raw/CONTROLS.json` | full suite |

## Where NOT to make changes

- **Do not edit `tmp/upstream/`** — it is regenerated by `npm run extract:upstream` and gitignored.
- **Do not edit `src/data/frameworks/iso27001.ts`** directly — it parses `_raw/CONTROLS.json`. Edit the JSON.
- **Do not bypass `validate:mappings`** by skipping CI — the orphan check is the only standing line of defense against silent drift.

## Anatomy of an IsoControl

```ts
// Management System clauses (4.1 - 10.x): 25 controls.
// No n80053 / nis2 / iso22301 / iso27017 / ct / sd fields upstream.
interface ManagementClauseControl {
  id: string;            // "4.1", "5.2", ...
  name: string;
  isoDesc: string;
  cat: "Management System";
  nistFunc: "GOVERN" | "IDENTIFY" | "PROTECT" | "DETECT" | "RESPOND" | "RECOVER";
  nistCat: string;       // "GV.OC"
  nistSub: string;       // "GV.OC-01, GV.OC-02" or "N/A"
  soc2: string;
  cis: string;
  pci: string;
  ce: string;
  caf: string;
  notes: string;
}

// Annex A controls (A.5.1 - A.8.34): 93 controls. All fields populated.
interface AnnexAControl extends ManagementClauseControl {
  cat: "Organizational" | "People" | "Physical" | "Technological";
  n80053: string;
  nis2: string;
  iso22301: string;
  iso27017: string;
  ct: string;            // "Preventive" | "Detective" | "Corrective" | ", "-joined
  sd: string;            // "Governance and Ecosystem" | "Protection" | "Defence" | "Resilience"
}
```

Cross-ref fields are **comma-separated strings**, not arrays. `parseCrossRefs()` in `mapping-engine.ts` handles parsing, trimming, and `N/A`-treatment. Always go through that helper — never split the string yourself.

## Invariants enforced by `npm run validate:mappings`

1. **No orphan refs.** Every id in a comma-separated cross-ref string must exist as a leaf node in the target framework's hierarchy.
2. **No isolated frameworks.** Every framework key in `frameworkPropKeys` must receive at least one inbound ISO reference.
3. **Reverse-lookup consistency.** `getIsoControlsForRef(controls, field, ref)` must return the source control id for every `(control, field, ref)` triple declared.

A violation of any of these is, by definition, a regression and must block CI.
