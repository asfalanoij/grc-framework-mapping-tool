## The integrity contract (READ BEFORE EDITING DATA)

The cross-framework mapping graph is enforced by:

- **`src/data/_raw/CONTROLS.json`** — the source of truth. 118 ISO controls with comma-separated cross-refs to 10 other frameworks.
- **`src/domain/mapping-engine.ts`** — the only place that parses cross-refs. Use its helpers (`parseCrossRefs`, `getMappingsForControl`, `getIsoControlsForRef`, `getTransitiveMappings`). Do not re-implement.
- **`src/domain/mapping-integrity.test.ts`** — three invariants (zero orphans / inbound coverage / reverse round-trip). Wired into `npm run validate:mappings`. CI gates on it before typecheck.

**Hard rules:**

1. **Any edit to `src/data/_raw/CONTROLS.json` MUST be followed by `npm run validate:mappings` (must exit 0) before you commit.**
2. **Cross-refs are comma-separated strings, not arrays.** Always parse via `parseCrossRefs()` from `mapping-engine.ts`.
3. **Do not bypass the CI gate** (`npm run validate:mappings` runs in `.github/workflows/ci.yml` before typecheck).
4. **Do not edit `src/data/frameworks/iso27001.ts` to add or change controls** — it parses the raw JSON. Edit the JSON.
5. **Do not commit `tmp/`** — it's gitignored and regenerated by scripts.
6. **The hub-and-spoke topology is intentional** (ISO 27001 is the center). Do not propose flattening it to a central crosswalks table without explicit user consent.

## Repository conventions

- **File size budget:** files < 800 lines, functions < 50 lines. Many small files > few large files.
- **Test colocation:** `*.test.ts(x)` next to the file under test (e.g. `mapping-engine.test.ts` next to `mapping-engine.ts`). Not in a `__tests__/` subfolder.
- **Coverage gates (CI-enforced):**
  - `src/domain/**` — 100% lines/functions, 95% branches
  - `src/services/**`, `src/store/**` — 80% across the board
  - Global floor — 70%
- **Commit format:** `<type>(<scope>): <description>`. Types: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `perf`, `ci`. Examples in `git log --oneline`.
- **Branch naming for milestone work:** `m<NN>/s<N>-<slug>` (e.g. `m9/s1-baseline`, `m11/s3-e2e`). Off the milestone integration branch (e.g. `data-integrity-rebuild` for M9-M11).
- **Always create a NEW commit** for fixes after pre-commit hook failures, never amend.

## What broke before (lesson from M9-M11 rebuild, 2026-05-17)

A prior session was perceived as "chaotic" with cross-framework interconnectedness "sacrificed." Forensic investigation (`docs/UPSTREAM_DIFF.md`) proved the data was actually intact — local `CONTROLS.json` matches upstream prinnyo byte-for-byte. The user-perceived issue was:

- No UI surface ever displayed a control's full cross-framework neighborhood at a glance — only populated mappings were rendered, so missing or sparse mappings were invisible.
- No CI gate prevented future data drift.
- No forensic record existed to prove the data was correct.

The M9-M11 rebuild (see `docs/M11_RETRO.md`) added all three: CI gate, neighborhood view with visible empties, forensic doc.

**Avoid this failure mode in future:** if the user complains the data is wrong, run `npm run validate:mappings` and `npm run extract:upstream` + diff FIRST. Don't assume rot until you've measured.
